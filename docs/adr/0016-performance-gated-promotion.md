# 0016: 本番へ昇格できるのは、性能試験まで成功した検証環境と同じ source tree だけにする

- 状態: Accepted
- 日付: 2026-10-31
- 関連: Issue #270（[ADR-0010](./0010-deploy-order.md) を置き換え）、Issue #262、Issue #220

## 背景

[ADR-0010](./0010-deploy-order.md) は、リリースを「マイグレーション → content の同期 → API → 画面」の順に適用し、失敗した段階で停止すると定めた。CI の検証環境リリースは smoke test の直後に成功を記録し、本番はその記録と同じ source tree だけを反映していた。

Workers Free の CPU 上限による強制終了は HTTP 200 の smoke test では検出できない。#262 では本番で 528 件を測定し、Workers Logs と cf-ray を照合して強制終了がないことを手動で確認した。この確認を本番反映の前に毎回行わなければ、CPU 障害を含む版が smoke test だけを根拠に本番へ進み得る。

ADR-0010 の決定3（CI の段階の並び）を変えるため、新しい ADR で置き換える。適用順序と失敗時の停止（決定1・2）は変えない。

検討した代替案:

- 本番反映後に測定する: 障害を本番で初めて検出するため採らない。本番への追加負荷も避ける。
- 測定を別 workflow で行い、結果を後から参照する: 測定中の別デプロイを排他できず、測定した版と記録した版の対応が崩れ得るため採らない。
- 応答時間の悪化で失敗にする: 検証環境の共有インフラの揺らぎで誤停止しやすい。導入当初は警告に留め、比較の実績を見てから判断する。

## 決定

1. リリースは引き続き「マイグレーション → content の同期 → API → 画面」の順に適用し、どの段階で失敗しても後続を実行しない（ADR-0010 の決定1・2を引き継ぐ）。
2. 検証環境の CI リリースは、事前検査、マイグレーション、同期、API、API の確認、Web、smoke test、性能測定、CPU ログ照合、成功の記録の順に進める。本番の CI リリースは性能測定と CPU ログ照合を持たず、smoke test の次に成功を記録する。
3. 性能測定は、決められた測定条件（対象ルート、HTML/RSC、件数、順序、キャッシュ無効、最初の異常で停止、再試行なし）を満たして全件が完了した場合だけ成功とする。CPU ログ照合は、測定した全 request の cf-ray を同じ時間帯・同じ Web version の invocation log と1対1で対応付け、CPU 上限による強制終了などの異常な outcome が1件もない場合だけ成功とする。ログの欠落・サンプリング・取得失敗・version の不一致は成功に含めない。
4. 検証環境の成功記録は、性能測定と CPU ログ照合の結果（測定条件の識別子・判定・警告を含む）を持つ。応答時間・CPU 時間の悪化は警告として記録し、それだけでは失敗にしない。
5. 本番の事前検査は、直近の検証環境の成功記録が同じ source tree・同じ測定条件で性能試験に成功していること、その記録の Web/API version が検証環境で稼働中の version と一致することを確認する。満たさなければ D1・Worker を変更する前に停止する。性能試験の結果を持たない成功記録は、性能試験に成功したものとみなさない。

## 境界

- 性能試験は検証環境だけで行う。本番への負荷試験、同時アクセスの負荷試験、Lighthouse / Core Web Vitals の自動化は対象外である。
- 本番 Web を最初に Vinext へ切り替えるときは、Web の段階だけを手動で実行する（Issue #221）。この手順は CI リリースではないため、決定2の段階を持たない。
- 復旧（ロールバック）は Worker の version を指定して行う別の手順であり、D1 の状態は戻らない。復旧後は成功記録による証明を無効にする。
- 警告の閾値、ログの待ち時間、測定条件の具体値、必要な権限は運用の手順とコードが扱う。測定条件を変えた場合は以前の結果と比較せず、本番の事前検査も新しい条件で成功した記録だけを受け付ける。
- 測定は検証環境の固定ユーザーと検証用 D1 を使い、本番データを複製・更新しない。

## 検証

- [deployment.test.mjs](../../scripts/deployment.test.mjs): 環境ごとの段階を決められた順序で実行し、どの段階で失敗しても後続を実行しない。性能試験の証跡がない・古い・条件が異なる検証記録では本番を拒否する
- [performance.test.mjs](../../scripts/performance.test.mjs): 応答異常・CPU 強制終了・ログ欠落・version 不一致・サンプリングを失敗とし、性能悪化は警告に留める
- [deployment-cli.test.mjs](../../scripts/deployment-cli.test.mjs): 実際の適用 CLI が性能試験の成功後にだけ検証環境の成功を記録し、性能証跡のない記録では本番を変更前に拒否する
