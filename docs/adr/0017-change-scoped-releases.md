# 0017: デプロイに影響する変更だけを、Worker ごとに反映する

- 状態: Accepted
- 日付: 2026-11-05
- 関連: Issue #286（ADR-0016 を置き換える）

## 背景

ドキュメントや AI ハーネスだけの変更でも、両環境で Web/API をビルドしていた。Worker は別々に配備できるため、変更のある Worker に対象を絞る。

ADR-0016 の決定1・2の Worker 適用対象と、決定5の source tree 全体の一致を変更する。ドキュメント更新を検証環境で省略すると、tree 全体の一致では本番昇格を止めてしまう。性能試験の成功記録は維持し、配備対象ソースの一致を別途確かめる。

直前の push との差分だけを使う案は、失敗したリリースの変更を取りこぼすため採らない。ファイルの許可リストだけを対象にする案も、新しい構成ファイルを検知できないため採らない。

## 決定

1. 自動リリースは、対象環境で最後に成功したリリースと比較し、変更のある Worker だけをビルド・配備する。ドキュメント・ハーネス・テストなど、配備に影響しないと明示したファイルだけの変更ではリリースしない。未知のパスは両 Worker の対象とする。共通コード・教材・共通依存関係の変更も両方を対象とする。
2. 初回、成功記録がロールバックで無効になった場合、比較元を取得できない場合、手動実行では両方を対象とする。片方を省略する場合は、稼働中 version が比較元の成功記録と同じであることを変更前に確認する。計画後に成功記録が変わった場合も停止する。
3. リリースの順序・失敗時の停止、毎回の migration/content sync、smoke test、検証環境の性能測定・CPU ログ照合と成功記録は ADR-0016 の決定1〜4を引き継ぐ。対象外 Worker のビルド・配備だけを省略し、実際に稼働する両 Worker の version で検証する。
4. 本番昇格では、直近の検証成功記録の commit/tree を Git と照合し、配備に影響する全ファイルのパス・モード・blob ID が本番候補と一致することを要求する。tree 全体が異なっても、差分が決定1の除外対象だけなら許可する。性能証跡と元の tree・run・両 Worker version の対応、現在の測定条件、検証環境の実 version の一致は ADR-0016 の決定5から引き継ぐ。

## 境界

- パスの判定は CI とリリースで共用する。API のクライアント生成コードなど Web の実行時依存になるファイルは両方の対象とする。具体的なパスはコードと運用文書に置く。
- PR の品質検査は維持し、Worker のビルドだけを変更範囲に合わせる。ワークフロー自体をパスで除外して必須チェックを未完了にしない。
- 環境 Variables/Secrets や手動の配備変更は Git の比較対象に含められない。設定を反映し直す場合や、省略した Worker の version が変わっていた場合は、手動実行で両方を再配備する。
- ロールバック、初回の Vinext 切替、性能測定の条件と秘匿情報の扱いは従来どおりとする。部分配備でも互換性の検査を省略しない。

## 検証

- [deployment-changes.test.mjs](../../scripts/deployment-changes.test.mjs): 除外対象、片方の変更、共通変更、削除・改名、比較不能時の全対象化を検証する。
- [deployment-cli.test.mjs](../../scripts/deployment-cli.test.mjs): 対象 Worker だけの配備、稼働 version と比較元の検査、ドキュメントだけが異なる本番昇格と実装が異なる場合の拒否を検証する。
- [deployment.test.mjs](../../scripts/deployment.test.mjs): 段階の順序・失敗時の停止と、性能証跡の検査を検証する。
