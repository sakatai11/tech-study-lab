# 0007: 学習分析の集計境界を UTC で固定する

- 状態: Accepted
- 日付: 2026-10-14
- 関連: Issue #242（`docs/design.md` の旧 4.4 節・旧 7.3 節から移行）

## 背景

学習分析（`/analytics`・`/home`）は、週次の推移、連続学習日数、SRS の定着度、誤答ランキングを表示する。日付の区切りや区分の定義が API・共有スキーマ・画面で食い違うと、同じ数字が画面ごとに変わる。さらに、通信中に日付が変わったときに、受信側の検証が失敗する。

## 決定

1. 集計の日付境界は UTC とする。
2. 週次の推移（`GET /analytics/weekly`）は、当日を含む直近7日を古い順に返し、解答がない日も0件で返す。
3. 「今週の学習時間」の今週は、UTC の月曜 00:00 から現在までとする。学習時間は「閲覧したレッスンの所要時間（frontmatter の `estimatedMinutes`）の合計」と「解答の反応時間の合計」で近似する。
4. 連続学習日数は、教材の閲覧または解答が1件以上ある UTC の日を数える。当日に活動がない場合は前日から遡る。
5. SRS の定着度の分布は、`due_at <= now` を「復習待ち」として先に分類し、残りのうち `interval_days >= 21` を「習得済み」、それ以外を「学習中」とする排他的な3区分とする。
6. 習得済みの問題数（`masteredQuestionCount`）と領域別の習得率は、`interval_days >= 21` の問題を数え、復習待ちかどうかで除外しない。そのため、同じデータでも定着度の分布の「習得済み」より多くなりうる。
7. 誤答ランキングは2回以上解答した問題だけを対象にし、丸める前の誤答率の降順、解答数の降順、`questionId` の昇順で並べて上位10件を返す。誤答率は小数第1位に丸めて返す。
8. 学習コントリビューション（`GET /analytics/heatmap`）は、UTC の当日を終点とする直近182日を返し、解答がない日は0件で補う。
9. 当日を終点とする期間は API の集計時刻で決める。受信側のスキーマは現在時刻に依存させない（通信中に UTC の日付が変わっても検証を通す）。

## 境界

- 対象は、解答ログ・閲覧ログ・SRS 状態から作る集計値すべてである。
- 利用者のタイムゾーンでの表示は扱わない。導入する場合は、この ADR を置き換える。
- 忘却曲線や復習タイミングの予測は対象外。

## 検証

- [analytics-service.test.ts](../../apps/api/src/services/analytics-service.test.ts): UTC と月曜の週境界、7日・182日の補完、連続学習日数、定着度の排他的な3区分と習得済み問題数の違い、誤答ランキングの並びと上位10件
- [analytics.integration.test.ts](../../apps/api/src/analytics.integration.test.ts): middleware のユーザーだけを集計し、週次・定着度・誤答ランキングの契約を満たす
- [api.test.ts](../../packages/shared/src/schema/api.test.ts): 共有スキーマが7日の連続・昇順・UTC の曜日、182日の連続、誤答率の丸めと順位を検証する。固定した過去の日付で検証しており、現在時刻に依存しない
