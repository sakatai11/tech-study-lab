# 0011: 取り込み済みのマイグレーションは変更せず、追加で直す

- 状態: Accepted
- 日付: 2026-10-14
- 関連: Issue #242（`docs/design.md` の §12.6 から移行）。元の判断は Issue #194

## 背景

D1 のマイグレーション履歴は、適用済みのファイル名と SQL に依存する。Git に取り込んだマイグレーションを後から書き換えたり改名したりすると、適用済みの環境と新しい環境でスキーマが食い違う。また、本番に適用できなくなる。

## 決定

1. Git に取り込まれた Drizzle のマイグレーション（SQL のファイル名と本文、`meta/*_snapshot.json`）は、変更・削除・改名しない。修正が必要なら新しいマイグレーションを追加する。
2. `meta/_journal.json` は既存の entry を同じ順序のまま保ち、新しい entry を末尾に追加するだけとする。
3. 破壊的な変更（列の削除、型の変更、NOT NULL の追加）は原則として避け、追加を中心にする。やむを得ない場合は「新しい列を追加 → データを移行 → 古い列を削除」の段階的なリリースで行う。
4. CI は PR の base と比べて、既存のマイグレーションと snapshot の削除・改名・内容の変更、journal の既存 entry の変更・削除・並べ替えを拒否する。新しいマイグレーションと snapshot の追加は許可する。

## 境界

- ローカル D1 の履歴を、同じ SQL の現在のファイル名に合わせる修復は例外として許す。条件と手順は運用の手順が扱い、本番の履歴の書き換えには使わない。
- スキーマ変更の進め方（生成・ローカル適用・テスト）は `d1-migration` スキルが扱う。

## 検証

- [check-migration-immutability.test.mjs](../../scripts/check-migration-immutability.test.mjs): 新しいマイグレーション・snapshot・journal の追加を許し、既存のマイグレーションと snapshot の削除・改名・内容の変更を拒否する
